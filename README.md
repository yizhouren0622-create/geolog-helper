# 寻宝手记 · Windows 本地 Geocaching 日志助手

选择照片、点选描述，预览确认后向 Geocaching.com 发布日志的 Windows 本地工具。支持地图 / 名称 / 经纬度选点、FTF / TFTC 快捷按钮、DNF 日志、自动保存草稿、照片压缩与去 EXIF，以及六步使用教程。无需 AI API。

本项目是基于 c:geo 开源接口实现适配的独立工具，不是 Geocaching 或 c:geo 官方产品。

## 安装与启动

需要 Windows 10/11、已加入 PATH 的 Python 3.11 或更高版本，以及可访问 PyPI、Playwright 下载站和 Geocaching.com 的网络。

1. 下载本仓库 ZIP 并解压，或克隆仓库。
2. 首次双击 `install.cmd`。它会创建项目内的 Python 环境、安装固定版本依赖，并下载兼容的火狐组件；完成后自动打开助手。
3. 以后双击 **启动日志助手.cmd** 或 `start.cmd` 即可，无需重复安装。助手会在专用火狐窗口打开。

服务运行时也可打开 http://127.0.0.1:8765 。程序只监听本机地址。运行环境和浏览器组件需在本机安装，源码仓库不附带这些大型文件。

## 写一篇日志

1. 点击“登录 Geocaching”，在打开的专用火狐窗口自行登录 Geocaching.com。回到“寻宝手记”标签页点击“检查登录”。不要关闭这个专用窗口，登录状态保存在本机独立配置目录中。
2. 选择地区，用名称或坐标定位，在地图标记或结果列表中点“选择”；也可直接粘贴 GC 编号。核对实际寻宝日期，再点“找到了”“没找到 DNF”“留言”或“参加活动”。
3. 照片可以多选，也可跳过。点选实际发生的描述；FTF（First to Find）和 TFTC（Thanks for the Cache）各有独立按钮。FTF 仅允许“找到了”类型，切换到 DNF 会移除首找、找到、签名描述。点选时保留手动写的其他文字；重新生成会先确认。
4. 点击“预览并发布”，核对地点、日期、正文、照片后点击“确认，一键发布”。这个按钮会公开发布到 Geocaching.com。

照片会在本地生成最长边 2000 像素的 JPEG 副本，移除副本 EXIF（含 GPS）；不修改原照片。每篇先支持最多 10 张、原图每张不超过 24MB。支持 JPG/PNG/WebP；HEIC 请先转换为 JPG。这里的 10 张是助手自己的限制，并不表示网站的官方限制。

## 地图和名称选点

- 地图使用本地随附的 Leaflet 和 OpenStreetMap 底图；默认定位上海，可切换北京、深圳、香港、澳门、台湾。底图加载受网络影响，失败时仍可使用列表、坐标和官网入口。
- 支持十进制度（`31.2304, 121.4737`）和度分（`N31 13.824 E121 28.422`），顺序是纬度、经度。坐标为 WGS84，不做 GCJ-02 偏移。
- 点击地图空白处设置查询中心，拖动 / 缩放后点击“搜索当前地图范围”；名称也在当前范围内匹配。查询范围过大时请先放大地图。
- 官网有时忽略名称筛选，所以助手会额外核验名称，显示匹配数和实际检索的候选数量；一次名称查询最多扫描 1000 个候选，可继续检索。
- 数据取自当前账号可见的官网返回结果。没有提供坐标的点只出现在列表，不猜测位置，也不绕过账号权限。官网拒绝接口时会显示错误，仍可通过“官网地图”选择。
- 点“官网地图”后，在专用火狐里打开某个藏宝点详情，再回助手点“带回官网选中的点”。这个操作只读，不会发布日志。

## 数据更新

重点地区按近似地理范围查询，并不声称是完整行政边界。上海、北京、深圳、香港、澳门、台湾每 **15 天**更新一次，分页读取，每区单次上限 **5000 条**。超过上限会显示“未完整”和实际数量。遇到 HTTP 429 会尊重 Retry-After（缺省暂停至少1小时），停止后续地区请求；已下载的分页立即入库并保留恢复游标。24小时内可续更，较旧游标会重新查询以减少数据顺序变化的影响。旧索引中未在本次返回的点不会被自动认定为已归档，请以官网详情为准。

全球数据按 **6 个日历月**更新，但**不附带全球全量数据库，也没有预置可用的全量来源**。官方 API 需申请合作伙伴权限。可在“藏宝点数据与自动更新”中配置你有权使用、无需令牌或密码的公开 HTTPS CSV 来源（也支持 `.csv.gz`）：

```csv
gc,name,lat,lng,type,status
```

`lat,lng` 可留空；必须使用真实且有权获取的数据。程序逐行导入，单个文件声明大小限 1 GB、最多 500 万条，来源覆盖范围和更新质量由提供者决定。解析失败会回滚本次导入、保留旧索引，不会把失败时间当成成功更新。全球来源未配置时显示“未配置”，不会假装完成全球同步。

助手运行且浏览器会话可用时，会定期检查到期数据。关闭期间的到期工作会在之后补做。数据状态、实际数量、最近及下次时间均可在页面下方查看。独立维护入口如下，不会发布日志，也不会主动弹出登录窗口：

```powershell
.runtime\Scripts\python.exe sync_catalog.py --scope regions
.runtime\Scripts\python.exe sync_catalog.py --scope global
.runtime\Scripts\python.exe sync_catalog.py --scope regions --region shanghai --force
```

`--region` 只更新选定地区（可重复指定）。`--force` 忽略15天更新日期，仍然遵守官网限流冷却；冷却期间不会向官网发请求。

本次部署另有 Codex 定时跟进：地区每15天、全球每6个月尝试维护。它依赖电脑和 Codex 可用，不随 GitHub 源码自动安装到别人的电脑。登录过期或网络失败会保留旧数据，需要时由用户重新登录。

## 使用教程

首次打开会显示六步教程：登录、地点、照片、描述、预览、之后。可用“上一步”“下一步”阅读，也能直接点步骤跳转。“查看操作位置”会收起教程并标出对应位置，点右下角“继续使用教程”即可返回。收起后，左侧“使用教程 · 跟着做一次”随时可重新打开。

教程只展示说明，不填写示例草稿、不上传照片，也不发布日志；可以等有真实记录时再使用。

## 草稿与补传

草稿、照片副本和上传进度保存在 `data/`。关闭网页后仍然保留。再次双击启动文件会复用已运行的服务。没有接入收费 AI API，日志文字来自本地点选组合。

文字上传成功后会立即保存 GL 编号。照片失败时再次发布只处理未完成的照片；照片上传成功但标题失败时，只重试标题。网络中断导致结果无法确认时，助手会停止自动重发。请通过“到官网查看”核对，再关联已有 GL 编号，或确认照片是否已经存在。只有在官网确认没有时才能选择重传。正文发布后在助手中锁定，需要修改时到官网编辑。

目前不处理 Trackable 动作、收藏点、维护报告、日志删除、批量自动提交，也不会从照片自动推断藏宝点或寻宝经历。每篇日志由你选择并确认。

## 来源与数据

开源筛选和许可记录见 `THIRD_PARTY.md`。本地网页只监听 127.0.0.1。照片和正文仅在你确认发布时通过网站接口发往 Geocaching.com；登录也在该官网完成。查询藏宝点时，会向 Geocaching.com 发送选定区域、坐标和名称关键词；显示底图时会从 OpenStreetMap 请求地图瓦片。网页没有云端存储或 AI 服务。请勿把 `data/firefox-profile/` 或先前的 `data/browser-profile/` 分享给别人，它们可能包含浏览器登录状态。

火狐组件在 `.browsers/`，使用 Playwright 提供的兼容版本。它与平时安装的 Firefox 配置分开，不更改系统默认浏览器，也不读取平时浏览器的登录信息。Edge 的登录状态不会自动迁移，需要在火狐中自行登录一次。

项目源码采用 Apache-2.0，许可见 `LICENSE`。运行环境在 `.runtime/`；换电脑时重新运行 `install.cmd`。依赖版本固定在 `requirements.txt`。

`data/`（含浏览器登录状态、草稿、照片）、`.runtime/`、`.browsers/` 和诊断日志已列入 `.gitignore`，不属于源码仓库。请使用源码仓库分发软件，不要分发自己安装后的整个目录。
